# 星泉視覺實驗室

以繁體中文星泉程式，在桌面與網頁執行相同的 MediaPipe ONNX 模型。右側「選擇範例」下拉選單提供「人體姿態」與「臉部關鍵點」兩個範例，分別呈現三十三個人體關鍵點與骨架，以及四百六十八個臉部關鍵點與眼睛、嘴唇、眉毛和臉部輪廓。選擇「使用圖形加速」時，兩個平台均使用 WebGPU；也可明確選擇中央處理器。影像與模型推論都在本機執行。

將支援姿態追蹤與 ONNX 推論的最新星泉編譯器完整發佈套件加入 `PATH`，確認可直接執行 `aqua`，並安裝 Node.js 以準備臉部模型及執行網頁伺服器，再使用 Windows PowerShell 5.1 或更新版本執行。已使用 `20261013-125208-8402312f` 發佈套件驗證；較舊的套件可能沒有姿態追蹤介面。

```powershell
./建置.ps1
./建置.ps1 -驗證圖形加速
# 僅建置網頁：
./建置.ps1 -略過桌面
```

桌面執行 `dist/星泉視覺實驗室.exe`；網頁執行 `node 網頁伺服器.mjs` 後開啟顯示的網址。部署至網站時使用 HTTPS。先選擇範例，再點選推論方式以載入該範例的模型並請求攝影機權限。停止或切換範例都會釋放攝影機與模型，清除影像、關鍵點與效能數值；切換後再點選推論方式啟動。下拉選單也可用 Enter／空白鍵開啟，上下方向鍵選擇，Enter 確定，Backspace 關閉選單。桌面攝影機沿用星泉的 FFmpeg 配接器，須讓 `ffmpeg` 可從執行路徑找到。

攝影機提供六百四十乘四百八十的影格，擷取與顯示均保持原始比例，以留邊方式填滿目標尺寸。人體姿態範例先執行人物偵測，再依臀部中心、身體尺度與方向建立旋轉裁切區域，送入姿態模型。熱圖細化後的關鍵點會還原到原始影格座標，並以自適應濾波降低抖動。連續影格沿用追蹤區域，失去人物時重新偵測；每隔一點五秒也會重新定位，避免裁切區域漂移。人物可以偏離畫面中央或側轉。

臉部範例先將影格留邊縮放為一百二十八乘一百二十八的 RGB 張量，使用 BlazeFace 偵測臉部；最可信臉部周圍的重疊候選以信心加權平均。依眼睛位置建立旋轉正方形裁切區域，放大至臉框的一點五倍，送入一百九十二乘一百九十二的 Face Mesh 模型，再將四百六十八組三維座標還原至原影格。攝影機模式沿用既有繪圖後端整批旋轉裁切，只將模型尺寸的像素傳回星泉；無視窗的影像驗證則使用星泉雙線性取樣。模型選擇中央處理器時，繪圖仍沿用原有 P2D 後端。臉部存在機率達百分之七十五才顯示，失去臉部立即清除關鍵點。多人時顯示最可信的一張臉；建議面向攝影機，讓整張臉清楚入鏡。此範例每格重新偵測，因此完整影格耗時可能高於姿態範例。

可見性及存在機率都必須達到百分之七十五，且關鍵點位於影格內，才顯示骨架。人物信心僅表示模型判斷畫面有人，不代表每個關鍵點同樣準確。多人時追蹤最可信的一人；嚴重遮擋、人物過小或大量身體部位離開畫面時，模型仍可能誤判，建議讓主要身體部位清楚入鏡。

`姿態模型.aqua` 呼叫核心的雙語姿態追蹤介面。像素以影像物件整批傳送；人物偵測解碼、裁切、座標還原與濾波都執行相同的核心 Wasm，無逐像素星泉陣列轉換。`臉部模型.aqua` 使用通用 ONNX、RGBA 像素陣列與既有繪圖介面，由共用星泉程式完成解碼與座標還原，不需要修改編譯器。`準備臉部模型.mjs` 在已校驗的原始模型前加入 RGBA 通道擷取、浮點轉換、NCHW 排列與正規化節點；權重不變，影像張量可整批傳送，不需要逐像素呼叫星泉函式。`姿態驗證.aqua`、`臉部驗證.aqua` 及對應的圖形加速驗證使用空白影像驗證模型與空白拒絕，不需要攝影機。建置預設驗證兩個範例的中央處理器推論，加入 `-驗證圖形加速` 可要求兩個範例的桌面 WebGPU 驗證。介面分別顯示完整影格處理耗時、模型耗時與實際影格率；完整影格耗時包含擷取、圖片轉換及關鍵點處理，影格率另包含繪製與排程時間。

`中文介面.aqua` 集中既有繪圖協定識別碼；所有專案宣告、函式呼叫、變數、註解及使用者介面均使用繁體中文，沿用其他星泉專案慣例。

模型來自 OpenCV Zoo 的 [人物偵測](https://github.com/opencv/opencv_zoo/tree/8e2b658d1007864a24cc2cf0e5b4288c74b32584/models/person_detection_mediapipe)與[姿態關鍵點](https://github.com/opencv/opencv_zoo/tree/1f19f821d68288feff2ef5c53993b33da74b1509/models/pose_estimation_mediapipe)，採 Apache 2.0 授權，授權全文保留於 `模型/模型授權.txt`。

臉部偵測與 Face Mesh 使用 [yakhyo 的 MediaPipe ONNX 移植](https://github.com/yakhyo/mediapipe-face-mesh-onnx/tree/add50e0f486405c96695812f9a9b9b89a485892b)，權重源自 Google MediaPipe，採 Apache 2.0 授權。模型取自 `weights` 發佈版本，授權保留於 `模型/臉部模型授權.txt`，來源與輪廓索引出處記錄於 `模型/臉部模型來源.txt`。

首次建置若缺少模型會下載並驗證，之後可離線建置。網頁封裝包含四個模型、推論引擎與共用姿態處理程式，執行時不使用第三方內容傳遞網路。建置腳本使用環境路徑中的 `aqua`，相容 Windows PowerShell 5.1。

額外的真實影像驗證位於 `驗證/臉部影像驗證.aqua`，測試四百六十八個關鍵點、鼻眼嘴幾何位置，以及臉部消失後清除結果。將上游 `assets/inputs/man_smiling.jpg` 存為 `驗證資料/人臉.jpg` 後執行：

```powershell
aqua build 中文介面.aqua 臉部模型.aqua 驗證/臉部影像驗證.aqua --root . --assets 模型 --assets 驗證資料 --entry 驗證/臉部影像驗證.aqua -o dist/影像驗證.wasm
aqua run dist/影像驗證.wasm
```

網頁驗證使用 Playwright 與 Chrome 的模擬攝影機，涵蓋兩個範例的 CPU／WebGPU、臉部影像、下拉選單、鍵盤切換及資源釋放。先使用 FFmpeg 準備固定影格，再執行 `node 驗證/網頁驗證.mjs`；需要可匯入的 `playwright`，或以 `AQUARIUS_PLAYWRIGHT` 指定其模組路徑。也會自動尋找相鄰 AquariusLangTW 專案的 Playwright 套件。報告與截圖輸出至 `dist/驗證/`。

```powershell
ffmpeg -y -i 驗證資料/人臉.jpg -vf "scale=640:480:force_original_aspect_ratio=decrease,pad=640:480:(ow-iw)/2:(oh-ih)/2" -frames:v 1 驗證資料/攝影機.png
ffmpeg -y -loop 1 -i 驗證資料/攝影機.png -t 2 -r 30 -pix_fmt yuv420p 驗證資料/攝影機.y4m
node 驗證/網頁驗證.mjs
```
